# dotty v0.4.0

Dotty v0.4.0 adds conservative managed checkouts, improves cleanup maintenance, and tightens several existing workflows.

## Highlights

- Added `.dotty/managed-checkouts.tsv` for editable Git repositories that dotty may clone and safely fast-forward during `install`, `update`, or the focused `dotty checkouts` command.
- Exposed managed-checkout metadata to install actions through `DOTTY_MANAGED_CHECKOUT_*` environment variables.
- Added advisory `DOTTY_CLEANUP_RETIRE_AFTER` dates so completed one-shot cleanup definitions can identify when they are candidates for manual retirement.
- Preserved registry order when existing entries are updated.
- Batched Git ignore checks during traversal to reduce repeated Git process startup.
- Refreshed public onboarding, uninstall, contribution, and release documentation.

## Guard configuration change

The public-content guard now reads patterns from one machine-wide file at `${XDG_CONFIG_HOME:-$HOME/.config}/public-content-guard/patterns`.

The legacy `.githooks/sensitive-content-patterns` source, `--patterns-file` option, `PUBLIC_CONTENT_GUARD_PATTERN_FILE`, and `PUBLIC_CONTENT_GUARD_PATTERNS` environment variable were removed. Move any remaining patterns into the machine-wide file before updating.

## Install notes

The public curl installer continues to track `main`:

```bash
curl -fsSL https://raw.githubusercontent.com/jackokerman/dotty/main/install.sh | bash
```

Existing installations can update with `dotty self-update` or their normal `dotty update` flow. No migration is required unless the removed guard pattern inputs were still in use.
